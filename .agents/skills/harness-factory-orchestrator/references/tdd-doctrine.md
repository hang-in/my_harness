# TDD 교리

1. Red: 변경할 행위를 재현하는 가장 작은 실패 테스트나 검증을 먼저 만든다.
2. Green: 통과시키는 최소 구현만 작성한다.
3. Refactor: 통과 상태에서만 구조를 정리하고 매 단계 재검증한다.

- 구조 변경과 행위 변경을 한 단위에 섞지 않는다.
- 전체 관련 테스트와 정적 감사를 통과해야 완료다.
- 에이전트는 커밋·브랜치 변경을 하지 않는다.
- 파괴적 롤백을 금지하고, 범위 한정 복구와 사용자 승인을 사용한다.
- 테스트 가능한 코드에만 TDD를 적용하고 문서·탐색 작업에는 성공 기준 검증을 사용한다.
